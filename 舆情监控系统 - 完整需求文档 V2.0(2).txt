一、系统定位与目标
1.1 系统定位
本系统为纯展示型舆情监控 Web 平台
├── 无需用户注册/登录
├── 无客户端 App
├── 通过网页直接向访问者展示舆情数据
└── 用户通过页面按钮、筛选器、跳转链接
    自助查询感兴趣的舆情内容
1.2 系统目标
核心目标：
1. 自动采集微博热门话题数据
2. 对话题内容进行情感分析
3. 利用 GNN 模型预测情感趋势
4. 综合判断舆情风险等级
5. 以可视化网页形式对外展示全部分析结果
1.3 用户角色重新定义
角色设计（简化为两类）：

┌─────────────────────────────────────────────────┐
│  后台运维人员（内部）                             │
│  ├── 直接操作服务器                              │
│  ├── 管理爬虫任务启停                            │
│  ├── 维护数据库                                  │
│  └── 模型更新部署                                │
└─────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────┐
│  网页访问者（外部，无需登录）                     │
│  ├── 查看热门话题列表                            │
│  ├── 点击话题查看详细分析                        │
│  ├── 查看情感分布图表                            │
│  ├── 查看词云                                    │
│  ├── 查看情感趋势预测                            │

└─────────────────────────────────────────────────┘

4.2 前后端交互方式
交互协议：
├── REST API（常规数据查询）
│   ├── GET  /api/topics              获取话题列表
│   ├── GET  /api/topics/:id          获取话题详情
│   ├── GET  /api/topics/:id/sentiment 获取情感分析数据
│   ├── GET  /api/topics/:id/wordcloud 获取词云数据
│   ├── GET  /api/topics/:id/users    获取活跃用户列表
│   ├── GET  /api/topics/:id/prediction 获取预测数据
│   ├── GET  /api/dashboard           获取大屏汇总数据
│   └── GET  /api/alerts              获取预警列表
│
└── WebSocket（大屏实时推送）
    └── ws://host/ws/dashboard
        每5分钟推送最新的舆情等级和预警信息

八、关键 API 接口定义
8.1 话题列表接口
GET /api/topics
Query参数：
├── page:        int  = 1        （页码）
├── page_size:   int  = 12       （每页数量）
├── keyword:     str  = ""       （搜索关键词）
├── time_range:  str  = "7d"     （1d/3d/7d/30d）
├── level:       int  = 0        （0=全部，1-5=具体等级）
└── sort_by:     str  = "heat"   （heat/risk/time）

响应示例：
{
  "code": 200,
  "data": {
    "total": 86,
    "page": 1,
    "items": [
      {
        "topic_id": "xxx",
        "topic_name": "某热门话题",
        "read_count": 12000000,
        "discussion_count": 85000,
        "opinion_level": 3,
        "level_color": "#FAAD14",
        "pos_ratio": 0.35,
        "neu_ratio": 0.30,
        "neg_ratio": 0.35,
        "rank_time": "2024-01-15 10:30:00",
        "heat_trend": "up"        // up/stable/down
      }
    ]
  }
}
8.2 情感分析数据接口
GET /api/topics/:id/sentiment
Query参数：
└── source_type: str = "all"   （all/post/comment）

响应示例：

  "code": 200,
  "data": {
    "overall": {

    ],

      { "day": "2024-01-09", "hour": 14, "neg_intensity": 0.6 }

8.3 词云数据接口
GET /api/topics/:id/wordcloud

九、数据处理流程总览
┌─────────────────────────────────────────────────────────────┐
│  Step 1：爬虫采集（每30分钟）                                 │
│  微博热搜 → 话题列表 → 帖子+评论+用户信息                    │
│  写入：tb_topic / tb_weibo_post / tb_comment / tb_user      │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 2：文本清洗（实时/爬取后触发）                          │
│  去除表情符号、URL、特殊字符、广告词                          │
│  更新：content_clean 字段                                    │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 3：情感分析（每2小时）                                  │
│  BERT-Chinese 模型推理                                       │
│  写入：tb_sentiment                                          │
│  更新：tb_user.activity_score                               │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 4：热词提取与词云生成（每天01:00）                      │
│  jieba 分词 → 词频统计 → 词云图片生成                        │
│  写入：tb_hot_word                                           │
│  缓存：Redis（词云图片Base64，TTL=24h）                      │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 5：GNN情感预测（每天02:00）                             │
│  构建用户关系图 → 时序图快照 → 模型推理 → 未来情感分布        │
│  写入：tb_prediction                                         │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 6：舆情等级判断（每天03:00 / 实时触发）                 │
│  综合评分 = 情感×0.4 + 传播×0.25 + 影响力×0.2 + 热度×0.15  │
│  更新：tb_prediction.opinion_level                          │
│  写入：tb_alert_log（等级≥3时）                             │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌──────────────────────────▼──────────────────────────────────┐
│  Step 7：缓存刷新（等级判断完成后）                           │
│  更新 Redis 中的 API 缓存                                    │
│  通过 WebSocket 推送最新等级到大屏前端                       │
└─────────────────────────────────────────────────────────────┘
十、开发阶段计划
Phase 1（第1~2周）：环境搭建与数据采集
├── 搭建 Docker 开发环境
├── 创建 MySQL 数据库及全部表结构
├── 完善爬虫模块（对齐字段，解决反爬问题）
├── 搭建 FastAPI 基础框架
└── 验证数据入库流程

Phase 2（第3~4周）：分析模块开发
├── 文本清洗 Pipeline
├── BERT 情感分析模型接入与测试
├── 活跃用户筛选逻辑
├── jieba 热词提取与词云生成
└── 对应 API 接口开发与联调

Phase 3（第5~6周）：GNN预测模块开发
├── 用户关系图构建脚本
├── 离线数据集制作
├── GNN 模型训练与评估
├── 预测接口封装
└── 舆情等级计算模块

Phase 4（第7~8周）：前端开发与系统集成
├── Vue3 项目初始化与路由配置
├── 首页 + 话题总览页开发
├── 话题详情页（四个Tab）开发
├── 舆情大屏开发（ECharts + WebSocket）
├── 前后端接口联调
└── 系统测试与性能优化
